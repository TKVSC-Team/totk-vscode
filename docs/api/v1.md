## Overview

TKVSC exposes a **hybrid addon model**:

| Integration style | When to use |
|-------------------|-------------|
| **Standard VS Code `contributes`** | Commands, menus, custom editors, grammars, settings - no API required |
| **`contributes.tkvsc` manifest** | Declarative formats, game profiles, archive patterns, bridge handlers |
| **`TkvscApi` programmatic surface** | Runtime registration, raw archive I/O, bridge access, project/game detection |

Core returns `TkvscApi` from `activate()`. Addon extensions declare:

```json
{
  "extensionDependencies": ["TKVSC-Team.totk-vscode"]
}
```

and obtain the API after core activates.

**What the API does *not* expose:** internal FS provider hooks, canonical save propagation internals, individual `totk-editor.*` command implementations, or direct access to the SQLite index query layer. Addons register **capabilities**; core pipelines consult registries.

## Quick start

```typescript
import * as vscode from 'vscode';

const TKVSC_ID = 'TKVSC-Team.totk-vscode';

export async function activate(context: vscode.ExtensionContext) {
  const api = await vscode.extensions.getExtension(TKVSC_ID)?.activate();
  if (!api || api.apiVersion !== 1) {
    void vscode.window.showErrorMessage('This addon requires TKVSC API v1.');
    return;
  }

  api.onDidReady(() => {
    console.log('Projects:', api.getProjectRoots());
    console.log('Active game:', api.getActiveGameProfile().id);
  });

  context.subscriptions.push(
    vscode.commands.registerCommand('my-addon.hello', async (treeItem) => {
      const root = api.resolveProjectRoot(treeItem);
      if (!root) return;
      // ...
    }),
  );
}
```

## Versioning and stability contracts

### `api.apiVersion`

```typescript
readonly apiVersion: 1
```

Increments only on **breaking** changes to `TkvscApi`. Additive methods within v1 are documented in [CHANGELOG.md](CHANGELOG.md) without bumping the version.

Always guard:

```typescript
if (api.apiVersion !== 1) {
  // handle unsupported version
}
```

### Stable outside `apiVersion`

These are compatibility contracts for the editor and addons but are **not** tied to `api.apiVersion`:

| Contract | Examples |
|----------|----------|
| Command IDs | `totk-editor.*` - use in menu `when` clauses |
| View IDs | `totk-editor.archives`, `totk-editor.gameDump` |
| URI schemes | `sarc`, `totk-disk`, `totk-dump` |
| TKMM layout | `.tkproj`, `options/Group/Option` (via built-in adapter) |

### Settings namespace

User-facing core settings use **`TKVSC.*`**. Addon settings should use your own prefix (e.g. `myAddon.cliPath`). Game addons typically contribute `TKVSC.<gameId>.romfsPath` via `romfsSettingsKey` on their game profile.

## Obtaining the API

```typescript
const ext = vscode.extensions.getExtension('TKVSC-Team.totk-vscode');
const api = await ext?.activate() as TkvscApi | undefined;
```

**Activation order:** Your addon's `extensionDependencies` ensures TKVSC activates first. Subscribe to `api.onDidReady` for Projects tree readiness — the event **replays** for listeners registered after `activate()` returns.

**Type-only consumption:** Until `@tkvsc/api` is published to npm, copy types from `src/api/` or reference the monorepo path. Re-exported types from `src/api/index.ts`:

- `TkvscApi`, `TkvscBridgeAccess`, `TkvscTreeItemLike`
- `FormatRegistration`, `BridgeHandlerRegistration`
- `GameProfile`, `GameProfileRegistration`
- `ProjectAdapter`, `ProjectOptionRef`
- `TKVSC_EXTENSION_ID`, `TKVSC_VIEWS`, `TKVSC_ARCHIVE_CONTEXT`

## `TkvscApi` interface

Complete surface as of v1 (Phases 1–4):

```typescript
interface TkvscApi {
  // Metadata
  readonly apiVersion: 1;
  readonly extensionId: string;
  readonly views: typeof TKVSC_VIEWS;
  readonly contextValues: typeof TKVSC_ARCHIVE_CONTEXT;

  // Lifecycle
  readonly onDidReady: vscode.Event<void>;

  // Projects & I/O
  resolveProjectRoot(item: unknown): string | undefined;
  getProjectRoots(): string[];
  readRawBytes(uri: vscode.Uri): Promise<Uint8Array>;
  writeRawBytes(uri: vscode.Uri, data: Uint8Array): Promise<void>;
  getBridge(): TkvscBridgeAccess;

  // Format registry (Phase 2)
  registerFormatHandler(registration: FormatRegistration): vscode.Disposable;
  registerBridgeHandler(registration: BridgeHandlerRegistration): vscode.Disposable;

  // Game profiles (Phase 3)
  registerGameProfile(registration: GameProfileRegistration): vscode.Disposable;
  getActiveGameProfile(): GameProfile;
  getGameProfile(gameId: string): GameProfile | undefined;

  // Project adapters (Phase 4)
  registerProjectAdapter(adapter: ProjectAdapter): vscode.Disposable;
  detectProjectAdapter(projectRootPath: string): ProjectAdapter;
  detectProjectAdapterAsync(projectRootPath: string): Promise<ProjectAdapter>;
  getProjectAdapters(): ProjectAdapter[];
}
```

## Stable constants

### `extensionId`

```typescript
readonly extensionId: string  // always 'TKVSC-Team.totk-vscode'
```

### `views`

Use in `contributes.menus` `when` clauses. Prefer `api.views.archives` in code instead of hardcoding strings.

| Key | Value | Sidebar |
|-----|-------|---------|
| `archives` | `totk-editor.archives` | **Projects** (mod project browser) |
| `gameDump` | `totk-editor.gameDump` | **Game Dump** (read-only dump mirror) |
| `gameDumpSearch` | `totk-editor.gameDumpSearch` | Dump search webview |

**Example `package.json` menu:**

```json
{
  "menus": {
    "view/item/context": [{
      "command": "my-addon.packageAsTkcl",
      "when": "view == totk-editor.archives && viewItem == archiveRoot",
      "group": "2_package@1"
    }]
  }
}
```

Equivalent in code: `view == ${api.views.archives} && viewItem == ${api.contextValues.archiveRoot}`.

### `contextValues`

`viewItem` strings set on the **Projects** tree. Defined in [`src/api/constants.ts`](../../src/api/constants.ts).

#### Project roots and files

| Key | Value | Meaning |
|-----|-------|---------|
| `archiveRoot` | `archiveRoot` | Top-level project folder in sidebar - **primary target for project commands** |
| `archiveProjectDir` | `archiveProjectDir` | Logical sub-project directory (multi-mod workspace) |
| `archiveProjectDirActive` | `archiveProjectDirActive` | Active logical sub-project |
| `archiveDir` | `archiveDir` | Ordinary directory on disk inside project |
| `archiveVirtualDir` | `archiveVirtualDir` | Directory inside a nested archive |
| `archiveFile` | `archiveFile` | File on disk in project |
| `archiveVirtualFile` | `archiveVirtualFile` | File inside an archive |
| `archivePackage` | `archivePackage` | Archive container (`.pack`, `.sarc`, etc.) |

#### TKMM options tree (built-in `TkmmProjectAdapter`)

| Key | Value | Tree node |
|-----|-------|-----------|
| `tkmmOptionsRoot` | `tkmmOptionsRoot` | `options/` folder |
| `tkmmOptionGroup` | `tkmmOptionGroup` | `options/<Group>/` |
| `tkmmOption` | `tkmmOption` | `options/<Group>/<Option>/` |
| `tkmmOptionActive` | `tkmmOptionActive` | Active option (star icon) |

Custom project adapters define their own `contextValues` strings; you must use matching values in your addon's menu `when` clauses.

## Virtual file system (URI schemes)

Addons should treat these schemes as TKVSC's virtual file system. They are **stable** but not part of `api.apiVersion`.

| Scheme | Writable | Description |
|--------|----------|-------------|
| `sarc` | Yes | Project/archive browser (nested SARC paths in `fsPath`) |
| `totk-disk` | Yes | On-disk project files; bridge conversion on save for editable formats |
| `totk-dump` | No | Read-only game dump mirror |
| `file` | Yes | Normal disk paths; `readRawBytes` / `writeRawBytes` work when not inside an archive segment |

**Path shape:** Nested archives appear as a single `fsPath` with archive extensions in path segments, e.g.:

```
E:\Mod\romfs\Pack\Title.pack\Actor\Foo.byml
```

`readRawBytes` / `writeRawBytes` resolve the outermost on-disk archive and inner locator automatically.

## Events

### `onDidReady`

```typescript
readonly onDidReady: vscode.Event<void>
```

Fires **once** after TKVSC registers the Projects archive tree and completes related startup wiring. **Replays immediately** for addons that subscribe after `activate()` resolves (normal `extensionDependencies` flow). Safe to call `getProjectRoots()` in the handler.

```typescript
api.onDidReady(() => {
  console.log('Projects:', api.getProjectRoots());
});
```

Does **not** wait for RomFS index builds or Python setup to finish.

## Project tree integration

### `resolveProjectRoot(item)`

```typescript
resolveProjectRoot(item: unknown): string | undefined
```

Extracts the **project folder path** from a Projects tree item passed to your command handler (first argument from context menus).

**Duck typing:** The item must have `contextValue?: string` and `resourceUri.fsPath`. You do not import internal `ArchiveTreeItem`.

**Resolution** delegates to registered `ProjectAdapter` implementations. For the built-in TKMM adapter:

| `contextValue` | Resolved path |
|----------------|---------------|
| `archiveRoot` | `resourceUri.fsPath` |
| `archiveProjectDir` / `archiveProjectDirActive` | `resourceUri.fsPath` |
| `tkmmOptionsRoot` | Parent of `options/` |
| `tkmmOptionGroup` | Project root (two levels up from group) |
| `tkmmOption` / `tkmmOptionActive` | Project root (three levels up from option) |
| Other | `undefined` |

**Example - spawn CLI on project root:**

```typescript
vscode.commands.registerCommand('my-addon.packageAsTkcl', async (item) => {
  const projectRoot = api.resolveProjectRoot(item);
  if (!projectRoot) {
    void vscode.window.showErrorMessage('Could not resolve project root.');
    return;
  }
  const cli = context.asAbsolutePath(path.join('bin', 'tkmm.exe'));
  // child_process.spawn(cli, ['package', projectRoot], ...)
});
```

### `getProjectRoots()`

```typescript
getProjectRoots(): string[]
```

All **active** project folder paths in the Projects sidebar (`fsPath` strings). For multi-mod workspaces this returns the logical active mod root per workspace folder, not only top-level workspace roots. Empty if the user has not added projects.

## Raw file I/O

### `readRawBytes(uri)`

```typescript
readRawBytes(uri: vscode.Uri): Promise<Uint8Array>
```

Returns **decompressed binary** for a URI.

| Situation | Behavior |
|-----------|----------|
| `file://` not inside an archive path | Direct `fs.readFile` |
| Path inside nested archive (`sarc://`, `totk-disk://`, or `file://` with archive segments) | Python bridge `export-temp` → read temp file → delete temp |
| Plain disk file inside project, not in archive | Direct read |

**Why not `vscode.workspace.fs.readFile`?** For unknown binary types inside archives, core's text pipeline returns an external-tool prompt string, not bytes. Custom editors (AINB, proprietary binary) must use `readRawBytes`.

**Errors:**

- Throws if Python is not configured and archive export is required.
- Message: *"Python environment is not ready. Run TKVSC: Set Up Python Environment first."*

### `writeRawBytes(uri, data)`

```typescript
writeRawBytes(uri: vscode.Uri, data: Uint8Array): Promise<void>
```

| Situation | Behavior |
|-----------|----------|
| Not inside archive | `fs.writeFile` |
| Inside nested archive | Bridge `write-raw` with base64 stdin |

**Errors:**

- Python required for archive writes.
- *"Cannot write binary data to an archive root."* if URI points at archive file itself without inner path.

### Custom editor pattern

```typescript
class AinbEditorProvider implements vscode.CustomReadonlyEditorProvider {
  constructor(private readonly api: TkvscApi) {}

  async openCustomDocument(uri: vscode.Uri): Promise<vscode.CustomDocument> {
    const bytes = await this.api.readRawBytes(uri);
    return { uri, model: parseAinb(bytes), dispose: () => {} };
  }
  // webview + save → api.writeRawBytes(uri, serialize(model))
}
```

Works for `sarc://`, `totk-disk://`, and archive paths opened from the Projects tree.

## Python bridge access

### `getBridge()`

```typescript
getBridge(): TkvscBridgeAccess
```

```typescript
interface TkvscBridgeAccess {
  bridgePath: string;           // absolute path to python/totk_bridge.py
  getPython(): string;         // configured Python 3.12 executable, or ''
  getBridgeEnv(): NodeJS.ProcessEnv;
  runBridgeJsonAsync: typeof runBridgeJsonAsync;
}
```

Use when `readRawBytes` / `writeRawBytes` are insufficient (custom bridge commands, one-off conversions).

**`runBridgeJsonAsync` signature (simplified):**

```typescript
runBridgeJsonAsync<T>(
  pythonExecutable: string,
  bridgePath: string,
  args: string[],
  stdin?: string,
  env?: NodeJS.ProcessEnv,
): Promise<T>
```

Bridge commands print JSON to stdout on success.

**Example:**

```typescript
const bridge = api.getBridge();
const python = bridge.getPython();
if (!python) return;

const result = await bridge.runBridgeJsonAsync<{ path: string }>(
  python,
  bridge.bridgePath,
  ['export-temp', diskArchivePath, internalLocator],
  undefined,
  bridge.getBridgeEnv(),
);
```

Prefer `readRawBytes` when possible - it handles temp file cleanup.

See [Bridge environment variables](#bridge-environment-variables) for env var reference.

## Format registration

Phase 2 capability. Registers how file extensions map to Python handler kinds, VS Code language IDs, and whether the editable text pipeline applies.

### `registerFormatHandler(registration)`

```typescript
registerFormatHandler(registration: FormatRegistration): vscode.Disposable
```

```typescript
interface FormatRegistration {
  extensions: string[];   // without dot: ['ainb', 'custom']
  handler: string;        // bridge kind, e.g. 'ainb'
  language?: string;      // VS Code language ID
  editable?: boolean;     // default true
}
```

**Effects:**

- Merged into `FormatRegistry` (with built-in TotK formats and other addons).
- Refreshes `tkvsc-handler-manifest.json` in core global storage.
- Python `_file_kind()` reads extension → handler mapping from manifest.

**Example - non-editable format for custom editor takeover:**

```typescript
api.registerFormatHandler({
  extensions: ['ainb'],
  handler: 'ainb',
  language: 'yaml',
  editable: false,
});
```

Setting `editable: false` prevents core from opening the file as converted text, letting your `customEditors` contribution handle it.

### `registerBridgeHandler(registration)`

```typescript
registerBridgeHandler(registration: BridgeHandlerRegistration): vscode.Disposable
```

```typescript
interface BridgeHandlerRegistration {
  kind: string;              // must match FormatRegistration.handler
  modulePath: string;        // absolute path to .py file
  readFunction?: string;     // default 'read_content'
  writeFunction?: string;    // default 'write_content'
}
```

Python module is loaded dynamically via `importlib` when the bridge encounters a non-builtin `kind`. Builtin kinds (`byml`, `msbt`, `aamp`, `asb`, `baev`, `xlnk`) are always handled inside `totk_bridge.py`.

**v1 note:** `Disposable` does not unregister handlers; restart required to remove API-registered entries.

### Built-in TotK formats (reference)

Loaded from [`config/coreFsExtensions.json`](../../config/coreFsExtensions.json). Addon formats **merge** with these; they do not replace them.

| Extensions | Handler | Language |
|------------|---------|----------|
| `byml`, `bgyml` | `byml` | `byml` |
| `msbt` | `msbt` | `msbt` |
| `asb` | `asb` | `json` |
| `baev` | `baev` | `json` |
| `belnk`, `bslnk` | `xlnk` | `yaml` |
| `rsizetable` | `rstb` | `totk-rstb` |

AAMP types: large built-in list in [`config/aamp-extensions.json`](../../config/aamp-extensions.json) plus `TKVSC.extraAampExtensions` and manifest `aampExtensions`.

## Game profiles

Phase 3 capability. Describes **which game** a dump/project targets: RomFS validation, compression backend, archive patterns, and per-game indexes.

### `registerGameProfile(registration)`

```typescript
registerGameProfile(registration: GameProfileRegistration): vscode.Disposable
```

```typescript
interface GameProfileRegistration {
  id: string;
  displayName: string;
  romfsSentinel: string;           // e.g. 'Pack/ZsDic.pack.zs'
  compressionBackend: string;      // 'totk-zstd' | 'plain-zstd-yaz0'
  romfsSettingsKey?: string;       // under TKVSC.* e.g. 'splatoon3.romfsPath'
  legacyRomfsSettingsKeys?: string[];
  indexing?: GameIndexingConfig;
  archivePatterns?: string[];      // regex strings for archive detection
  ainb?: GameAinbConfig;
}

interface GameIndexingConfig {
  enableRomfsSearch?: boolean;      // default true for new profiles
  enableCanonicalPaths?: boolean;   // default false; TotK sets true
  archiveExtensions?: string[];     // e.g. ['.pack', '.sarc', '.pack.zs']
}

interface GameAinbConfig {
  categoryDirs?: string[];          // dirs holding loose AINB, e.g. ['AI', 'Sequence']
  nodeDefinitionGlob?: string;      // '{category}' expands to each categoryDir
}
```

`ainb` tells the node definition harvester where this game keeps its AINB. It runs the first
time an AINB is opened for the game and writes a per-game catalog, so the node editor offers
the right nodes with the right defaults.

Both fields are optional and fall back to TotK's layout. Archives are always swept regardless,
so omitting the section costs only the loose files and definition tables outside TotK's
directory names - the node catalog itself is still built.

```json
"ainb": {
  "categoryDirs": ["AI", "AIGameCommon", "NetSequence", "Sequence"],
  "nodeDefinitionGlob": "{category}/NodeDefinition/Node.Product.*.aidefn.byml*"
}
```

A `nodeDefinitionGlob` without `{category}` is globbed once from the RomFS root, for a game
that does not group its definition tables by category.

**Built-in TotK profile:** [`config/games/totk.json`](../../config/games/totk.json)

| Field | TotK value |
|-------|------------|
| `id` | `totk` |
| `romfsSentinel` | `Pack/ZsDic.pack.zs` |
| `compressionBackend` | `totk-zstd` |
| `romfsSettingsKey` | `romfsPath` → `TKVSC.romfsPath` |
| `indexing.enableCanonicalPaths` | `true` |

### `getActiveGameProfile()` / `getGameProfile(gameId)`

```typescript
getActiveGameProfile(): GameProfile
getGameProfile(gameId: string): GameProfile | undefined
```

Active profile ID from `TKVSC.activeGameId` (default `totk`). `GameProfile` adds `source: 'builtin' | 'manifest' | 'api'`.

Users can switch the active profile from the Your Projects / Game Dump view title pickers (`totk-editor.selectActiveGame`) or settings. Each project stores its association in `.tkvsc` as `gameId`; Your Projects and `getProjectRoots()` only include projects whose `gameId` matches the active profile (missing `gameId` is treated as `totk`).

**Effects of active profile:**

- `getBridgeEnv()` sets `TKVSC_GAME_ID`, `TKVSC_COMPRESSION_BACKEND`, `TKVSC_ROMFS`, `TKVSC_ARCHIVE_EXTENSIONS`
- Dump tree index paths: `globalStorage/indexes/{gameId}/`
- Archive file detection uses profile's `archivePatterns`
- Canonical save propagation skipped when `indexing.enableCanonicalPaths === false`

### Compression backends

| ID | Description |
|----|-------------|
| `totk-zstd` | ZsDic dictionary ZSTD (TotK). Requires valid `romfsPath` with `Pack/ZsDic.pack.zs` for **recompression** on save. |
| `plain-zstd-yaz0` | Plain ZSTD decompress/compress and Yaz0. For games without ZsDic (e.g. Splatoon-style). |

Python dispatch: [`python/compression/__init__.py`](../../python/compression/__init__.py) reads `TKVSC_COMPRESSION_BACKEND`.

### Per-game index databases

```
{globalStorage}/
  indexes/
    totk/
      romfs-index.sqlite
      romfs-index.state.json
      canonical-paths.sqlite
      canonical-paths.state.json
    splatoon3/
      ...
  tkvsc-handler-manifest.json
  canonical-project-overlays.sqlite
```

Legacy indexes at globalStorage root are migrated to `indexes/totk/` on upgrade.

### Splatoon 3 example (manifest + settings)

```json
{
  "contributes": {
    "tkvsc": {
      "id": "splatoon3",
      "gameProfile": {
        "displayName": "Splatoon 3",
        "romfsSentinel": "Pack/Bootup.Nin_NX_NVN.pack.zs",
        "compressionBackend": "plain-zstd-yaz0",
        "romfsSettingsKey": "splatoon3.romfsPath",
        "indexing": {
          "enableRomfsSearch": true,
          "enableCanonicalPaths": false
        }
      },
      "archivePatterns": ["\\.(pack|sarc|genvb)(\\.zs)?$"]
    },
    "configuration": {
      "title": "Splatoon 3 (TKVSC)",
      "properties": {
        "TKVSC.splatoon3.romfsPath": {
          "type": "string",
          "default": "",
          "description": "Path to your Splatoon 3 RomFS dump."
        }
      }
    }
  }
}
```

Users set `TKVSC.activeGameId` to `splatoon3` when working with that game.

### `ProjectAdapter` interface

Full contract - [`src/projectAdapters/types.ts`](../../src/projectAdapters/types.ts). Reference implementation: [`src/projectAdapters/tkmmAdapter.ts`](../../src/projectAdapters/tkmmAdapter.ts).

```typescript
interface ProjectAdapter {
  readonly id: string;
  readonly displayName: string;
  readonly contextValues: {
    optionsRoot: string;
    optionGroup: string;
    option: string;
    optionActive: string;
  };
  readonly optionsDirName: string;       // TKMM: 'options'
  readonly projectMarkerFile?: string;   // TKMM: '.tkproj'

  isProjectRoot(projectRootPath: string): boolean | Promise<boolean>;
  supportsOptionsTree(projectRootPath: string): boolean | Promise<boolean>;

  resolveProjectRootFromTreeItem(
    contextValue: string | undefined,
    resourceFsPath: string,
  ): string | undefined;

  resolveOptionsProjectRoot(
    contextValue: string | undefined,
    resourceFsPath: string,
    workspaceRootPath: string,
    isArchiveRoot: boolean,
  ): string;

  getActiveOption(context, projectRoot): ProjectOptionRef | undefined;
  setActiveOption(context, projectRoot, group?, option?): Promise<void>;

  listOptionGroups(projectRoot: string): Promise<string[]>;
  listOptions(projectRoot: string, group: string): Promise<string[]>;
  createOptionGroup(projectRoot: string, groupName: string): Promise<void>;
  createOption(projectRoot: string, groupName: string, optionName: string): Promise<void>;

  askForOption(projectRoot: string): Promise<ProjectOptionRef | 'BASE_PROJECT' | 'BACK' | undefined>;

  listModRoots(projectRoot: string): string[];

  importProjects?(): Promise<string[]>;           // e.g. TKMM recent.json paths
  getImportSourceLabel?(): string;
  scaffoldNewProject?(projectFolderUri: vscode.Uri): Promise<void>;
}
```

**What core uses adapters for:**

| Feature | Adapter methods |
|---------|-----------------|
| Projects tree options hierarchy | `optionsDirName`, `contextValues`, `supportsOptionsTree` |
| `resolveProjectRoot()` | `resolveProjectRootFromTreeItem` |
| Active option / add-to-option | `getActiveOption`, `askForOption` |
| Import projects command | `importProjects` (all adapters) |
| Create project command | `scaffoldNewProject` |
| Canonical path import scan | `listModRoots` |

**Custom adapter checklist:**

1. Implement all required methods.
2. Choose unique `contextValues` strings for your tree.
3. Add `contributes.menus` entries with matching `when` clauses.
4. Call `api.registerProjectAdapter(adapter)` in `activate()`.
5. Optionally implement `importProjects` for external tool integration.

**v1 note:** Adapter `Disposable` does not unregister.

## Declarative manifest (`contributes.tkvsc`)

Core scans **all installed extensions** at startup (active or not) and merges contributions into registries. No VS Code native contribution point - TKVSC reads `package.json` directly.

### Full schema

```json
{
  "contributes": {
    "tkvsc": {
      "id": "optional-addon-id",
      "gameProfile": { /* GameProfileRegistration */ },
      "formats": [ /* FormatRegistration[] */ ],
      "aampExtensions": ["customext"],
      "archivePatterns": ["\\.(pack|sarc)(\\.zs)?$"],
      "bridgeHandlers": [{
        "kind": "mykind",
        "modulePath": "./python/my_io.py",
        "readFunction": "read_content",
        "writeFunction": "write_content"
      }]
    }
  }
}
```

| Key | Type | Description |
|-----|------|-------------|
| `id` | `string?` | Optional addon identifier; used as `gameProfile.id` fallback |
| `gameProfile` | object | Same fields as `registerGameProfile` |
| `formats` | array | Same as `registerFormatHandler` |
| `aampExtensions` | `string[]` | Extra AAMP container extensions |
| `archivePatterns` | `string[]` | Regex merged onto `gameProfile.archivePatterns` (root-level patterns combine with nested profile patterns) |
| `bridgeHandlers` | array | `modulePath` relative to **declaring extension root** |

Manifest contributions merge with built-in TotK config and any programmatic API registrations at activate time.

**Precedence:** Built-in → manifest scan → programmatic API (last writer wins per extension key in registry internals; avoid conflicting extensions).

## Bridge environment variables

`getBridge().getBridgeEnv()` returns these (plus `process.env`):

| Variable | Description |
|----------|-------------|
| `TKVSC_ROMFS` | Active game profile RomFS path |
| `TOTK_EDITOR_ROMFS` | Same as `TKVSC_ROMFS` (legacy alias) |
| `TKVSC_GAME_ID` | Active profile `id` |
| `TKVSC_COMPRESSION_BACKEND` | e.g. `totk-zstd` |
| `TKVSC_ARCHIVE_EXTENSIONS` | Comma-separated list from profile indexing config |
| `TKVSC_HANDLER_MANIFEST` | Absolute path to `tkvsc-handler-manifest.json` |
| `TOTK_TAG_PRODUCT_FORMAT` | From `TKVSC.tagProductFormat` |
| `TOTK_EXTRA_AAMP_EXTS` | Comma-separated extra AAMP extensions |
| `TOTK_BYML_INLINE_CONTAINER_MAX_COUNT` | From `TKVSC.bymlInlineContainerMaxCount` |
| `TOTK_PTCL_VECTOR_FORMAT` | From `TKVSC.ptclVectorFormat` |

Always pass `getBridgeEnv()` when invoking `runBridgeJsonAsync` so addon handlers and compression see the correct game context.

## Handler manifest (`tkvsc-handler-manifest.json`)

Written to core **global storage** on startup and when format/bridge handlers change. Path exposed as `TKVSC_HANDLER_MANIFEST`.

```json
{
  "version": 1,
  "extensionToHandler": {
    "byml": "byml",
    "ainb": "ainb"
  },
  "aampExtensions": ["baenv", "..."],
  "handlers": {
    "ainb": {
      "modulePath": "C:\\...\\addon\\python\\ainb_io.py",
      "readFunction": "read_content",
      "writeFunction": "write_content"
    }
  }
}
```

| Field | Description |
|-------|-------------|
| `extensionToHandler` | File extension (no dot) → handler kind |
| `aampExtensions` | Extensions treated as AAMP binary |
| `handlers` | Non-builtin kinds → Python module paths (absolute) |

Builtin kinds in Python (`byml`, `msbt`, `aamp`, `asb`, `baev`, `xlnk`) are **not** listed in `handlers`; they are implemented in `totk_bridge.py`.

## Python addon handler contract

Module referenced by `bridgeHandlers` / `registerBridgeHandler`:

```python
def read_content(
    file_data: bytes,
    logical_path: str,
    romfs_path: str = "",
) -> str:
    """Return editor text for read-disk / SARC text pipeline."""
    ...


def write_content(
    original: bytes,
    editor_text: str,
    logical_path: str,
    romfs_path: str = "",
) -> bytes:
    """Return new file bytes for save."""
    ...
```

Function names are configurable via `readFunction` / `writeFunction` (defaults: `read_content`, `write_content`).

For **binary-only** formats used with custom editors, register `editable: false` and use `readRawBytes` / `writeRawBytes` from the addon instead of the text pipeline.

## Integration recipes

### TKMM CLI addon (Phase 1)

Needs only: `resolveProjectRoot`, `views`, `contextValues`, standard VS Code menu.

```json
"menus": {
  "view/item/context": [{
    "command": "tkvsc-tkmm-cli.packageAsTkcl",
    "when": "view == totk-editor.archives && viewItem == archiveRoot"
  }]
}
```

### AINB / binary custom editor (Phase 1 + 2)

1. `contributes.customEditors` for `*.ainb`
2. `registerFormatHandler({ extensions: ['ainb'], handler: 'ainb', editable: false })`
3. Optional `registerBridgeHandler` if you want text pipeline support
4. `readRawBytes` / `writeRawBytes` in custom editor document provider

### Game format addon (Phase 2–3)

1. `contributes.tkvsc` with `gameProfile`, `formats`, `archivePatterns`
2. Ship Python handler modules + compression if not `totk-zstd`
3. Contribute `TKVSC.<gameId>.romfsPath` setting
4. Document that users set `TKVSC.activeGameId`

### Alternate project tool (Phase 4)

1. Implement `ProjectAdapter`
2. `registerProjectAdapter` in activate
3. Custom `contextValues` + matching menus
4. Optional `importProjects` for external recent-project lists

## v1 limitations

| Limitation | Workaround |
|------------|------------|
| `registerFormatHandler` / `registerBridgeHandler` / `registerGameProfile` / `registerProjectAdapter` disposables don't unregister | Reload window / restart extension host |
| No `registerExternalTool` on API yet | Use existing core external tools storage or spawn CLI directly |
| Single active game profile at a time | Switch `TKVSC.activeGameId` (view title game picker or settings) |
| `write-disk` bridge path may not cover all addon handler kinds | Use SARC pipeline or `writeRawBytes` |
| No published `@tkvsc/api` npm package | Copy types from `src/api/` |
